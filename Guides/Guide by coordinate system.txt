🧭В S.T.A.L.K.E.R. навигация и перемещение персонажей (как НПС, так и монстров) не основаны на свободном перемещении по 3D-пространству. Это иерархическая структура, где глобальный граф (Game Graph) управляет межлокационными перемещениями, а локальный граф (Level Graph) — движением внутри уровня.

Важно понимать, что координаты в формате x, y, z не являются глобальными. Каждая локация имеет собственную локальную систему координат, где точка (0, 0, 0) — это её центр. Это означает, что координаты (100, 0, -50) на Кордоне и те же (100, 0, -50) в Припяти — это совершенно разные точки в мире.

Именно поэтому прямая работа с векторами (vector():set(x, y, z)) возможна только в рамках одной локации. Для корректной навигации и взаимодействия между уровнями игра использует единый глобальный граф — Game Graph, где каждая точка представлена гейм-вертексом (game_vertex_id). Этот ID однозначно идентифицирует позицию в масштабах всей Зоны, а его локальное смещение хранится в левел-вертексе (level_vertex_id). Таким образом, вертексы — это «мост» между локальными координатами и глобальной структурой мира, без которого невозможна работа ALife и корректные переходы между локациями.


1. Двухуровневая система графов
Система состоит из двух связанных между собой графов:

Game Graph (Глобальный граф игры):
Это единая карта для всего Зоны, охватывающая все локации.
Имеет вершины (game_vertex или gvid)
Этот граф определяет, какие локации связаны между собой и как НПС могут перемещаться между ними в режиме ALife (оффлайн).

Level Graph (Локальный граф уровня):
Это навигационная сетка, индивидуальная для каждой локации.
Её вершины (level_vertex или lvid) — это мелкие точки, покрывающие всю проходимую территорию локации. По ним НПС ходят в онлайне и офлайне.
Каждая вершина level_vertex привязана к одной вершине game_vertex. Это связывает локальный и глобальный графы.


2. Как это работает на практике

Создание перехода:
В Level Editor на границе локаций ставится объект level_changer.
В его настройках указывается dest_game_vertex_id — ID вершины в Game Graph, на которую ведет переход.
Это создаёт ребро между вершинами двух разных локаций в глобальном графе.


Перемещение в офлайне (ALife):
Когда НПС находится вне зоны видимости игрока, он «спит» в офлайне.
Его перемещение управляется планировщиком на основе Game Graph.
НПС выбирает путь от своего текущего game_vertex к целевому game_vertex.
При этом он не прокладывает путь по локальным вершинам, а просто «телепортируется» (логически) от одной глобальной точки к другой, моделируя поход через локацию.
Перемещение в онлайне:
Как только НПС оказывается на той же локации, что и игрок, он «просыпается».
Его путь внутри локации прокладывается по Level Graph.
Игра использует level_vertex_id из game_vertex, чтобы определить, с какой точки локального графа НПС должен начать своё движение.


3. Территориальные маски и AI-сетка
Чтобы НПС не заходили в недоступные или неподходящие зоны, используется система территориальных масок в game.ltx и профилях НПС, они обеспечивают логическую целостность мира.


Если чего-то не хватает, то возможно добавить, но это приведет к перекомпиляции графов на всех уровнях. Так что добавлять что-либо надо заранее, потом этой возможности не будет.

game.ltx содержит справочники территорий, разбитых на 4 категории (location_0, location_1, location_2, location_3):
location_0: Название локации (Эскейп, Янтарь и т.д.).
location_1: Тип ландшафта (Равнина, Болото, Город и т.д.).
location_2: Тип местности (Здание, Дорога, Бурелом и т.д.).
location_3: Специфические зоны (Блокпост, Фабрика и т.д.).
У каждого типа существа (профиля) в его .ltx файле задана маска вида 255,3,255,255.
Каждое число в маске — это битовая маска, соответствующая одной из категорий location_X.
Например, 3 в location_1 означает, что НПС может ходить по территориям с индексами 001 (равнина) и 002 (склоны), так как 3 = 1 + 2 (биты 0 и 1 включены).
255 (или -1) означает «любая территория» в этой категории.
При выборе пути система фильтрует вершины графа, оставляя только те, чей тип местности соответствует битовой маске профиля НПС.


В ltx-e персонажей и монстров есть настройка маски, по которой будет выбираться доступная для данного персонажа территория:

[stalker_terrain]
255,3,255,255


terrain	= stalker_terrain; 255,3,255,255,0,1,   255,2,255,255,0,1,   

где:

первое число соответствует 		[location_0]

второе число соответствует	 	[location_1]

третье число соответствует 		[location_2]

четвертое число соответствует	[location_3]

чуть не забыл - так как в сталкере не работает функция table.maxn() - которая возвращает кол-во целочисленных индексов в таблице, то я пользуюсь ее самопальным аналогом, (который считает индексы всех типов - хоть числовые, хоть строковые - причем для числовых не важно идут ли они в математическом порядке или вразнобой) вызывая там где надо table_maxn(имя таблицы)

function table_maxn(tbl)
	local k = 0
	for _, v in pairs(tbl) do
		k = k + 1
	end
	return k
end

-- в sak.script кладем  
function get_lv_gv(level_name, pos) 
    local lg, ct 
    if level.name() == level_name then 
        lg = level_graph() 
        ct = cross_table() 
    else 
        lg = level_graph(level_name) 
        ct = cross_table(level_name) 
    end 
 
    local lv = lg:vertex_id(pos) 
    if not lg:valid_vertex_id(lv) then 
        lv = lg:nearest_vertex_id(pos) 
    end 
    local gv = ct:vertex(lv):game_vertex_id() 
    return lv, gv 
end 
 
function alife_create(section, level_name, pos) 
    local lv, gv = get_lv_gv(level_name, pos) 
    return alife():create(section, pos, lv, gv) 
end
