Язык программирования для скриптов - Lua

Следите за тем, что пишете в скриптах, произвольные символы вызывают вылеты, свои комментарии\заметки оставляем так:

-- мой коммент

Также можно закомментировать целый блок

--[[
   ваш код
   ещё код
]]

Далее пойдет речь об основных инструментах луа:

Переменные

Переменная это имя для значения в памяти, которое может быть любым. Переменные могут быть глобальные и локальные. При создании переменной она по умолчанию является глобальной, если не указано ключевое слово local перед ее именем:

x = 50 -- глобальная переменная
local var1, var2 = 10, 20 --локальные переменные(множественное присваивание)

Локальные переменные ограничены областью видимости блока(это может быть тело цикла, функции или модуля), в котором они объявлены.

Операторы сравнения

В языке LUA имеются 6 операторов сравнения: "==" (равно), "~=" (не равно), "<" (меньше), ">" (больше), "<=" (меньше или равно), ">=" (больше или равно).

Логические операторы

В языке LUA есть три основных логических оператора: "и" (and), "или" (or) и "не" (not). Эти операторы позволяют комбинировать логические значения и выражения для формирования более сложных условий.

Условия

Инструкция if(если) проверяет условие на истину, и выполняет последующие инструкции в случае истины. В случае неуспешной проверки(условие ложно), выполняется else(иначе) часть(если она присутствует). Если необходимо несколько else условий то их удобнее заменить elseif(иначе если) инструкциями, без необходимости закрывать каждую инструкцию с помощью end:

if предметов >= 0 then log1("Positive") end

if предметов > 0 then
    действие если предметов больше чем 0
elseif предметов == 0 then
    действие если предметов 0
elseif b ~= 3 then
    действие если предметов не 3
else
    действие если ни один из вариантов не прошел
end

Также условия могут быть вложены друг в друга:

if a > 0 then
    if b > 0 then
        функция1()
    else
        функция2()
    end
end

Оператор конкатенация строк '..'

Конкатенация строк - это операция объединения двух или более строк в одну новую строку. В программировании конкатенация строк является очень распространенной операцией, используемой для создания более сложных и информативных строковых значений.

local string1 = "Привет"
local string2 = "мир!"
local result = string1 .. " " .. string2
log1(result)  -- Результат: "Привет мир!"

Оператор ".." позволяет объединять как строки, так и числа или другие типы данных с помощью автоматического приведения типов. Однако при конкатенации разных типов данных может потребоваться явное преобразование в строку с помощью функции tostring().

Операторы таблиц '.', ':'

Для доступа к элементам таблицы, можно использовать оператор '.'

local t = {
  name = "John"
}
local n = t.name

А вот для доступа к методам таблицы, можно использовать оператор ':'

local t = {
  func = function (a, x)
    message(tostring(a) .. " = " .. x)
  end
}
t:func(5);  -- Результат table: 000002323E950AE0 = 5

Когда обращение к элемету таблицы осуществляется через оператор ":" и элемент является функцией, текущая таблица передается в функцию первым аргументом.

Функции

Функция это группа инструкций, которые выполняют какую-либо задачу. Можно написать свою функцию, объявив ее следующим способом:

local function functionName(arg1, arg2, arg3, ..., argn)
    value = ...
    ...
    return value
end

local - необязательная часть(функция будет локальной в случае такого объявления, т.е. доступной в рамках блока, в котором она объявлена).
functionName - имя нашей функции. arg1, arg2, arg3, ..., argn - аргументы функции, перечисленные через запятую
... - тело нашей функции, которое содержит все инструкции, которые необходимо выполнить.
return value - значение, которое функция возвращает. Является необязательным: если не указано, то подразумевается, что функция возвращает nil. Результат можно сохранить в переменную, передать в другую функцию, использовать в условии.
end - конец блока функции.

Также функция может возвращать несколько значений:

function find()
    ...
    return значение1, значение2
end

ещё иногда можно встретить вызовы функций, в которых не указан файл скрипта, например:

if not has_alife_info("storyline_actor_start") and

has_alife_info - это функция из g.script - глобального пространства Луа _G
выглядит красиво и компактно, но это лишняя нагрузка, лучше не злоупотреблять.

Ещё монжо встретить this - вызов функции create_items() из того же файла внутри, которого написана функция create_items_actor_nomsg()

function create_items_actor_nomsg()
	this.create_items()
end

Аргументы функций

в функциях часто можно встретить подобное:

dialogs.relocate_item_section(db.actor, "wpn_pm", "in")

dialogs - dialogs.script
relocate_item_section это функция из dialogs.script, а (db.actor, "wpn_pm", "in") это аргументы этой функции

то есть, если вы откроете dialogs.script и найдёте функцию relocate_item_section, то увидите:

function relocate_item_section(victim, section, type)

и вместо (victim, section, type) мы при вызове указали (db.actor, "wpn_pm", "in")

Когда в функцию не нужно ничего передавать делаем function имя_функции()

Функция может принимать переменное количество аргументов, для этого укажите «...» в качестве аргумента функции.

function max(...)
    local args = {...} -- массив аргументов
    if #args == 0 then return end -- если нет аргументов, то не выполняем инструкции ниже
    -- какое-то действие с этими аргуметами
end

вызов max(1,15,2,5,6,24,12)

В диалогах и логике:
первый аргумент это актор - главный герой, его клиентский объект
второй аргумент это нпс, в логике которого была вызвана функция, либо тот с кем мы ведем разговор - его клиентский объект

в оригинале диалоги не позволяют передать, что-то кроме актора и нпс, а вот в ОГСР есть поддержка передачи аргументов в функции, вызываемые из диалогов, например:

<precondition>my_script.test_func(123, true, nil, ...)</precondition>
<action>my_script.test_func(123, true, nil, ...)</action>

То есть в оригинале НЕЛЬЗЯ оформить action так:

<action>dialogs.relocate_item_section(db.actor, "wpn_pm", "in")</action>

Если указать после аргументов ... , то в функцию будут переданы стандартные аргументы, типа:
pSpeakerGO1->lua_game_object(), pSpeakerGO2->lua_game_object(), dialog_id, phrase_id
(актор, нпс, диалог, фраза)
если этого не сделать, то стандартные аргументы не будут переданы.

То есть если мы хотим взаимодействовать с нпс, обязательно делаем два аргумента actor и npc

function my(actor,npc)
	actor:kill(npc)
end

В логике похожая ситуация, функции вызываются например через on_info:

on_info = %=new_fire%

передается актор и нпс, при этом сама функция должна выглядеть:

function new_fire(actor, npc)
	npc:set_item(object.fire1, npc:best_weapon(), 1 ,1)  
end

т.е. видим что актор не участвует, но если не указать второй аргумент, не важно как вы записали первый - это будет актор

Для передачи других аргументов в логике, например, чисел - оформляем функцию так:

function new_fire(actor, npc, p)
npc:set_item(object.fire1, npc:best_weapon(), p[1] ,p[2])  
end

в логике:

on_info2 = %=new_fire(4:1000)%

в аргументы добавился третий - p

далее оно само понимает куда подставить 4, а куда 1000

вот ещё пример

function new_visual(actor, npc, p)
    data.visual_name = p[1] --визуал

вызов

on_actor_dist_le_nvis = 5 | %=new_visual(actors\neytral\stalker_neytral_rukzak_3)%

СПОСОБЫ ВЗАИМОДЕЙСТВИЯ С НПС И ПРОЧИМИ ОБЪЕКТАМИ

С нпс в функциях можно взаимодействовать не только через диалог или логику

Для начала определим локальную переменную obj - это будет клиентский объект, с ней будем взаимодействовать через клиентские методы, т.е. функции класса game_object, под взаимодействием понимается примерно следующее:

obj:set_money( 65000 ) установить количество денег 
obj:set_character_rank(1000) установить ранг
obj:set_npc_position(vector():set(-152.0,-18.0,-144.3))

Эти методы были добавлены в ОГСР

--установка отношений
obj:set_relation(game_object.friend, db.actor)

Для этого нужно определить сам объект:

local obj = level_object_by_sid(6)   	 -- стори айди
local obj = level.object_by_id(id)		 -- клиентский айди(он не известен за ранее, так как при новой игре назначается рандомно)

и так вот применять:

obj:set_item(object.fire1, obj:best_weapon(), 10 ,1000)

Есть ещё и серверные методы, обозначим как sobj.

определение серверных объектов:

local sobj = alife():story_object(6)	 -- стори айди
local sobj = alife():object("esc_wolf") -- получаем айди по имени из all.spawn

пример:

--убрать привязку к аи сетке
alife():use_ai_locations(sobj, false)
--удалить объект:
alife():release(sobj)

получение клиентского объекта по серверному, obj из sobj:

local sobj = alife():object("esc_wolf") -- Серверный объект
local obj = level.object_by_id(sobj.id) -- Клиентский объект

Теперь наоборот получаем серверный через клиентский

если это диалог\логика или какой-нибудь биндер нпс\какая-нибудь из схем, где передается self.object, то можно

function имя_функции(actor,obj)
   local sobj = alife():object(obj:id())

ещё можно попробовать так

function имя_функции(actor,obj)
   local sobj = obj:get_alife_object()

Вот яркий пример использования серверного метода через клиентский объект и как вызов из логики\диалога без дополнительных данных.

если в xr_effects.script добавить

function remove_object(actor, obj)
local sobj = obj and alife():object(obj:id())
	if sobj then
    	alife():release(sobj)
	end
end

то объект удалится, например, удаление рестриктора, после того как он отработал:

on_actor_outside = nil %=remove_object%

Теперь рассмотрим момент использования клиентских методов через логику/диалог

в xr_effects.script добавить

function kill_object(actor, obj)
	if obj then
		obj:kill(obj)
	end
end

а в логике нпс/диалоге сделать вызов и объект должен погибнуть, вызов:

on_info = {±инфо} %=kill_object%

или в диалоге

<action>xr_effects.kill_object</action>

Ещё есть функции, которые на вход требуют айди, то есть sobj.id или obj:id(), подойдет клиентский и серверный объект, например:

local sobj = alife():story_object(014)
local obj = level_object_by_sid(6)

--увести в оффлайн:
alife():set_switch_online(sobj.id, false) 
alife():set_switch_online(obj:id(), false) 

--поставить метку
level.map_add_object_spot(sobj.id, "green_location", "текст")
level.map_add_object_spot(obj:id(), "green_location", "текст")

Исользование методов класса game_object при спавне нпс через скрипт

Когда мы спавним нпс, его клиентская сторона образуется не сразу и использование методов класса game_object, т.е. клиентских приведет к вылету, поэтому есть такой вот способ, как без сейвлоадов сразу использовать клиентские методы на нашем нпс:

function spawn_client_spawn_manager()
	local sobj = alife():create("stalker",vector():set(-152.0,-18.0,-144.3),98126,45)
	level.client_spawn_manager():add(sobj.id, 65535,
    function (id, obj)
		obj:set_goodwill(-5000, db.actor)
    end
    )
end

можно чуть универсализировать функцию в _g.script

function client_spawn(section, pos, lv, gv, func)
    local sobj = alife():create(section, pos, lv, gv)
    level.client_spawn_manager():add(sobj.id, 65535, function(id, obj) func(id, obj) end)
end

и вызов

client_spawn("stalker",vector():set(-152.0,-18.0,-144.3),98126,45,function(id, obj)
    obj:set_goodwill(-5000, db.actor) 
	end)

Есть ещё нюансы, нпс должен быть на расстоянии не более 140 метров от гг, иными словами в онлайне(зависит от switch_distance).

В данной функции указываются координаты и секция вашего нпс, всё как обычно, а вот взаимодействие может быть разным, тут:

obj:set_goodwill(-5000, db.actor)

изменение отношения этого нпс к актору, параметр obj передаётся за счёт

function(id, obj)

поэтому структуру не менять, а само взаимодействие с obj можно сделать так:

utils.send_to_nearest_accessible_vertex(obj,107814)

то есть передаём как удобно.

Получение объекта заспавненного через скрипт

Таким образом определить нпс:

local sobj = alife():object("esc_wolf")

не получится, так как их имя секции превращается в "esc_wolf12445", т.е. к нему добавился айди, который заранее неизвестен

Поэтому их надо искать путем перебора всех объектов

Для совершение действий над клиентским объектом, заспавненным через скрипт по имени

function level_object_by_spawn( name )
        for a=1,65535,1 do
        local obj=level.object_by_id(a)
                if obj and string.find(obj:name(),name) then
                        return obj
                end
        end
end

Для совершение действий над серверным объектом, заспавненным через скрипт по имени

function alife_object_by_spawn( name )
        for a=1,65535,1 do
        local sobj=alife():object(a)
                if sobj and string.find(sobj:name(),name) then
                        return sobj
                end
        end
end

ОГСР версии (они приоритетнее)
Для совершение действий над клиентским объектом, заспавненным через скрипт по имени

function level_object_by_spawn( name )
	for id, sobj in alife():objects() do 
		local obj=level.object_by_id(sobj.id)
		if obj and string.find(obj:name(),name) then
			return obj
		end
	end
end

Для совершение действий над серверным объектом, заспавненным через скрипт по имени

function alife_object_by_spawn( name )
	for id, sobj in alife():objects() do 
		if string.find(sobj:name(),name) then
			return sobj
		end
	end
end

Для определения клиента:

local obj = level_object_by_spawn("esc_wolf")

Для сервера:

local sobj = alife_object_by_spawn("esc_wolf")

Использование функций в логике

Вызов функции:

%=название_функции%

Функция проверки:

{=название_функции}

Пример:

[logic]
active = sr_idle1

[sr_idle1]
on_timer = 10000 | %=название_функции% sr_idle

Функции проверки должны лежать в \gamedata\scripts\xr_conditions.script
Функции действия должны лежать в \gamedata\scripts\xr_effects.script

Метод\функции движка в скриптах

В некоторых скриптах можно увидеть такие моменты:

level.client_spawn_manager

и конечно же никакого файла level.script нет, а если и есть, то функции client_spawn_manager в нем точно нет, это так называемый движковый метод, большинство описано в lua_help.script

Функции в диалогах

В диалогах функции вызываются через action:

    <phrase id="121">
        <text>tutorial_wounded_give_medkit_121</text>
        <action>dialogs.transfer_medkit</action> 
    </phrase>

в инфопоршн аналогично:

	<info_portion id="escape_stalker_meet">
		<action>dialogs.transfer_medkit</action>
	</info_portion>

Но в инфо лучше не злоупотреблять - вылеты неинформативные.

dialogs это dialogs.script, а transfer_medkit это функция из этого скрипта

Так же в диалогах можно использовать функции проверки <precondition>, для того, чтобы некоторые фразы отображались, если соблюдены условия функции

            <phrase id="2">
                <text>tutorial_wounded_give_medkit_2</text>
                <precondition>dialogs.actor_have_medkit</precondition>
                <next>121</next>
            </phrase>

В данном примере диалог не выйдет на 2 фразу, пока не будет выполнено условие из <precondition>dialogs.actor_have_medkit</precondition>

Прекондишны можно ставить и на сам диалог, чтобы задать условие его появления.

    <dialog id="escape_trader_talk_level" priority="2">
        <precondition>escape_dialog.trader_alredy_give_job</precondition>
        <phrase_list>

В квестах функции проверки выглядят так <function_complete>Имя_файла.prov</function_complete>

		<objective>
			<text>name_pod_kvest_1</text>
			<function_complete>Имя_файла.prov</function_complete>
		</objective>

Оформление функций для проверки

function название_функции()
	if "набор условий" then
		return true
	else
		return false
	end
end

"набор условий" это нечто вроде if has_alife_info("инфопоршн1") and not has_alife_info("инфопоршн2") then
то есть, если получен "инфопоршн1" и не получен "инфопоршн2", то истина

или if sak.have_item_namber("af_medusa",1) and sak.have_item_namber("wpn_pm",1) then что означает, если получен 1 "af_medusa" и 1 получен "wpn_pm", то истина

ещё можно оформить так:

function timer()
  if "набор условий" then
    return true
  end
  return false

ЦИКЛЫ for

Циклы необходимы, когда нужно выполнить инструкцию или группу инструкций некоторое количество раз. Циклы в Lua бывают разных типов:

while

Выполняет инструкции пока заданное условие является истинным. Перед выполнением проверяет условие на истинность.

condition = true
while condition do
    condition = someFunc()
end

Числовой for

Обладает следующим синтаксисом: for var=exp1,exp2,exp3 do ... end, где exp1 - начальное значение, exp2 - конечное значение, exp3 - шаг. exp3 является необязательным(по умолчанию равно 1)

for i=1, 10 do log1(i) end

for i=20, 5, -1 do log1(i) end

Общий for

Позволяет пройтись по элементам, полученным от итерирующей функции(например, ipairs).

tbl = {1, 3, 5, 7, 9}
for _,element in ipairs(tbl) do
    log1(element)
end

repeat

Выполняет инструкции пока заданное условие является истинным. Проверяет условие на истинность после выполнения(т.е. выполнится как минимум один раз).

repeat
    condition = someFunc()
until condition

Также циклы могут быть вложены друг в друга:

for i=1,3 do
    for j=10,20 do
        log1(j)
    end
end

Инструкции break и return могут быть использованы для прерывания цикла. break прерывает цикл, в то время как return сразу же возвращает значение функции и завершает ее:

for i=0,10 do
    if i == 6 then
        log1(i)
        break
    end
end

Если имена следуют по шаблону, например, `npc_1`, `npc_2`... `npc_30` и списка нет:

    for i = 1, 30 do
        local name = "npc_" .. i
        local sobj = alife():object(name)
        if sobj then действие над sobj end
    end
